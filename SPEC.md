# Pipatab — Wireless Graphics Tablet for Artists

## Цель

Превратить iPad Pro (с Apple Pencil) в графический планшет без экрана для Windows 11.
Никакого зеркалирования экрана. Только ввод стилусом — быстро, стабильно, без лишнего.

## Как пользоваться

1. На ПК: запустить `Pipatab.exe` (порт по умолчанию 1701).
2. На iPad: открыть `http://<ip-компьютера>:1701` в Safari, добавить на экран «Домой» для полноэкранного режима.
3. Все настройки — на iPad: выбор монитора, кривая давления, hover.

Флаги сервера: `-port`, `-bind`, `-code` (код доступа в URL `?code=...`), `-monitor` (стартовый монитор).

## Архитектура

```
┌─────────────────────┐    WebSocket (binary + JSON)   ┌──────────────────────────┐
│   iPad Safari/PWA   │ ◄────────────────────────────► │    Windows 11 Server     │
│                     │                                │                          │
│  PointerEvent API   │  ── pen events (12 B, bin) ──► │  Единый Synthetic Pen    │
│  coalesced 240 Hz   │                                │  Device на выделенном    │
│  кривая давления    │  ◄── monitors / pong (JSON) ── │  OS-потоке               │
│  настройки, UI      │                                │  Per-Monitor V2 DPI      │
└─────────────────────┘                                └──────────────────────────┘
```

### Ключевые решения (стабильность и скорость)

- **Бинарный протокол** для событий пера: 12 байт/событие, без JSON-парсинга в горячем пути.
  Формат описан в `protocol.go` / `web/src/protocol.ts` (они должны совпадать).
- **Немедленная отправка** каждого DOM-события (плюс coalesced-сэмплы Apple Pencil до 240 Гц),
  без покадрового батчинга. TCP_NODELAY на сервере.
- **Один synthetic pen device на процесс**, созданный на залоченном OS-потоке при старте.
  Новое подключение вытесняет старое (`replaced`) — перезагруженная вкладка Safari всегда работает.
- **Восстановление state-machine Win32** (выстрадано практикой):
  - UP-кадр обязан прийти в координатах последнего принятого UPDATE — иначе
    `ERROR_INVALID_PARAMETER` и каскадный отвал контакта;
  - INCONTACT UPDATE без предшествующего DOWN (reconnect посреди штриха) повышается до DOWN;
  - инъекции впритык (коалесцированные пачки) Windows изредка (~0.1%) отвергает транзиентно —
    кадр повторяется после SwitchToThread (до 3 попыток); явные PerformanceCount ухудшают
    ситуацию — метки времени оставлены системными;
  - если кадр отвергнут окончательно посреди штриха — контакт немедленно
    переустанавливается DOWN-кадром в той же точке (разрыв — ноль сэмплов);
  - keep-alive: неподвижное перо не рождает DOM-событий, сервер сам повторяет последний
    контактный кадр каждые ~25 мс, чтобы контакт не протух внутри Windows.
- **Per-Monitor V2 DPI awareness** — физические пиксели на всех мониторах при любом масштабировании.
- **Backpressure**: при заторе Wi-Fi клиент отбрасывает только hover-пакеты, контактные — никогда.
- **Heartbeat в обе стороны**: транспортные ping каждые 5 с (сервер), app-ping каждые 2 с (клиент,
  даёт RTT в UI); мёртвый линк рвётся и переподключается с экспоненциальным backoff.
- **Wake Lock + visibilitychange**: экран iPad не засыпает; при сворачивании контакт пера
  принудительно отпускается.

## Возможности

- Давление (0–1024 у Windows), наклон X/Y, поворот (twist), ластик, баррел-кнопка
- Hover Apple Pencil (iPad Pro M2+) — курсор двигается без касания; отключается в настройках
- Кривая давления: монотонный кубический сплайн с 3 ручками + пресеты Soft/Linear/Firm,
  живой индикатор давления при рисовании
- Мультимонитор: реальные имена мониторов (QueryDisplayConfig), визуальная карта раскладки,
  активная область на iPad повторяет пропорции выбранного монитора
- Режим нескольких мониторов: галочки в списке выбирают 2+ дисплеев, перо маппится на их общий
  прямоугольник (union), рамки мониторов рисуются внутри рабочей области; точки в «мёртвых зонах»
  L-образных раскладок сервер прижимает к ближайшему выбранному монитору
- Настраиваемая рабочая область: кнопка рядом с настройками включает режим рамки с 4 угловыми
  хендлерами — размер, пропорции и положение области; перетаскивание внутри рамки двигает её целиком
- Живое давление: полоски raw/output и точка прямо на графике кривой; перо продолжает работать
  при открытой панели (подложка не перехватывает события пера)
- Настройки живут на iPad (localStorage) и переустанавливаются при каждом реконнекте

## Не входит (сознательно)

- Тачпад-режим, жесты пальцами, squeeze Apple Pencil Pro — возможно позже
- Зеркалирование экрана — принципиально нет
- Linux / macOS сервер — не планируется

## Стек и структура

- **Сервер:** Go + gorilla/websocket + WinAPI (без cgo)
- **Клиент:** TypeScript → esbuild → один `app.js`; статика встраивается в бинарник (`go:embed`)
- **Сборка:** `build.bat` (typecheck → bundle → `go build`), артефакт — один `Pipatab.exe`;
  версия вшивается из git-тега (`-X main.version`), релизы собирает GitHub Actions по тегу `v*` (см. `RELEASING.md`)

```
main.go               — CLI, старт
server.go             — HTTP + embed + /ws
session.go            — WebSocket-сессия, keepalive
hub.go                — владелец инжектора, политика единственной активной сессии
protocol.go           — бинарный + JSON протокол
injector_windows.go   — synthetic pen injection
monitors_windows.go   — перечисление мониторов + дружелюбные имена
dpi_windows.go        — Per-Monitor V2 DPI
web/
  index.html, app.css, icon.svg, manifest.webmanifest
  src/                — модули клиента (main, net, pen, pad, curve, curveEditor, protocol, settings)
  dist/app.js         — бандл (генерируется, в git не хранится)
```
